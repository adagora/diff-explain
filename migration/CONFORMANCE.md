# Conformance: freezing the oracles

**Stage 0. Do this before writing a single spec.**

A port graded only by "the tests I wrote from my own specs pass" grades the
specs, not the port. `meat` avoids that trap because several of its correctness
properties are byte-exact and language-neutral. Capture them while Go is still
the reference, and the port acquires a pass/fail signal that spec drift cannot
fake.

## The two free oracles

These need no harness at all.

### 1. The golden fixtures

`meat/testdata/python/` holds three real upstream commits, each as three files:

```
django-526b1b414d8e.diff        ← input: a real unified diff
django-526b1b414d8e.plan.json   ← input: a hand-authored edit plan, source coordinates
django-526b1b414d8e.golden.diff ← output: exact machine-rendered bytes
```

Applying a plan to a diff is pure, deterministic, and **hermetic — no model is
involved**. `TestPythonGoldenCommits` reads the plan from disk, compiles it, and
compares exact bytes; it additionally asserts semantic anchors (`mustContain` /
`mustNotContain`), expected move detection, fold counts, and absolute size
budgets. `meat/testdata/python/README.md` explains what each snapshot protects
and why each budget is what it is — read it before specifying anything.

This is the hard gate. Copy the whole directory into `testdata/` byte-for-byte
and port the test harness. If the TypeScript `compileEditPlan` reproduces those
three golden files exactly, the plan compiler, the mandatory import pass, the
fold renderer, the Python validators, and move detection are all correct
together.

### 2. The frozen prompt surface

Every string a model can see lives in a named constant so that `promptSurface()`
can render all of them through the real builders and hash the result
(`meat/rubric.go:48-62`). `RubricHash()` is **exported** and returns the first 8
bytes of that SHA-256 as hex (`meat/rubric.go:175-178`).

```sh
# from the repo root. The helper must live inside the module for the
# meat.dev/meat import to resolve — hence conformance/, not /tmp.
mkdir -p conformance/vectors conformance/rubrichash
cat > conformance/rubrichash/main.go <<'EOF'
package main

import (
	"fmt"

	"meat.dev/meat"
)

func main() { fmt.Print(meat.RubricHash()) }
EOF
go run ./conformance/rubrichash > conformance/vectors/rubric-hash.txt
```

**Verified at commit `f39f41d`, this prints `441f5e6e28ad3add`.** If it prints
something else, the prompt surface changed after this document was written —
re-baseline deliberately and note why, rather than assuming a typo.

If the TypeScript port produces the same hash, the entire model-visible prompt
surface — system prompt, rubric, all five user-prompt fragments, tool
descriptions, plan-feedback strings, and the protocol version — survived the
port byte-for-byte. That is an enormous amount of exactness for one line of
output, and it is the single cheapest high-value check in the project.

It also feeds `cacheKey` (`cmd/meat/cache.go:31`), so matching it means Go and
TypeScript builds share cache entries.

## Dumping the rest

Most engine functions are unexported, so a dump harness has to live inside
`package meat`.

> **The permitted additions to the Go tree**, all purely additive and all
> already written: one env-gated dump test per package
> (`meat/conformance_dump_test.go`, `cmd/meat/conformance_dump_test.go`), plus
> anything under `conformance/`. They follow the existing `UPDATE_GOLDEN=1`
> convention (`meat/testdata/python/README.md`), modify no existing file, and
> change no behavior. Nothing else in the Go tree may be touched for the
> duration of the port. Delete both dump tests when the port is complete.

**Stage 0 is done.** 111 vectors are checked in under `conformance/vectors/`,
generated by:

```sh
DUMP_VECTORS=conformance/vectors go test ./meat  -run TestDumpConformanceVectors
DUMP_VECTORS=conformance/vectors go test ./cmd/meat -run TestDumpCLIConformanceVectors
go build -o conformance/meat-go ./cmd/meat    # reference binary for differential runs
```

The harness is self-checked: its `plan-compile` vectors reproduce all three
checked-in `.golden.diff` files byte for byte (6,685 / 5,037 / 2,615 bytes,
matching `meat/testdata/python/README.md`).

```sh
DUMP_VECTORS=conformance/vectors go test ./meat -run TestDumpConformanceVectors
```

fixtures needed, and the language coverage is already there:

`analysis/` is not ported (it's recorded evaluation data), but its diffs are a
free multi-language corpus for the deterministic stages — and Rust and Go
exercise import-detection paths the Python testdata never reaches.

builder is not reachable from a pure function the way `toOpenAIInput` is. Cover
it in stage 1 from `meat/anthropic_test.go` instead, or extend the harness if a
seam appears.

Store each as `input → expected-output` pairs the TypeScript runner can read
directly, with no Go in the loop:

```
conformance/vectors/
  rubric-hash.txt
  prompt-surface.txt
  moves/django-526b1b414d8e.json
  split/python.original.b4096.json
  ...
```

Errors are outputs. Where a vector expects a rejection, record the exact message
— several tests assert on error text, and matching it keeps those tests portable.

## The TypeScript side

`test/conformance.test.ts` walks `conformance/vectors/` and asserts each. It has
no knowledge of what any vector means; it just checks bytes. Add it to the TODO
list early — it should exist and be failing before most of the port is written,
so every subsequent item can be measured against it.

Sequencing note: vectors for a stage only start passing once that stage is
ported. That is fine and expected. Track the pass count as the port's real
progress metric — it is far more honest than "files ported".

## Differential testing during stage 3

Keep a Go binary around:

```sh
go build -o conformance/meat-go ./cmd/meat
```

For any diff, both builds must agree exactly on every deterministic surface:
`-json` output shape, the elision manifest, cache keys, and chunk boundaries.
Only the model-dependent content of `smart_diff` may differ between runs, and
even that is fixed if both sides are driven by the same scripted model — which
is exactly what `scriptedModel` (`meat/meat_test.go:18`) and `modelFunc`
(`meat/chunk_test.go:23`) do. Port those fakes early; they make the agent loop
itself deterministic and testable.

## Rules

- **A vector is never regenerated to make a test pass.** If the port disagrees
  with a vector, the port is wrong until proven otherwise in writing.
- **Regenerating the goldens is forbidden during the port.** `UPDATE_GOLDEN=1`
  exists for deliberate corpus tuning, not for blessing a port's output. The
  budgets in `meat/testdata/python/README.md` are absolute.
- **If a vector genuinely encodes a Go bug**, record it in
  [`HAZARDS.md`](HAZARDS.md) with the analysis, keep the vector, and match the
  bug. Fixing behavior and porting behavior are separate projects; doing both at
  once means neither can be verified.
